# 数据结构说明

## 核心概念

系统采用**双维度**数据模型：
- **分类维度（What）**：道具是什么类型
- **归属维度（Who）**：道具属于谁

## PropItem 数据结构

```typescript
interface PropItem {
  name: string;              // 原始文件名
  displayName: string;        // 展示名称
  image: string | null;       // Base64图片
  
  // 分类信息
  classification: {
    type: 'furniture' | 'other';        // 大类
    category: string;                   // 分类名："起居"、"男主元素"
    categoryPath: string[];             // 完整路径：['家具', '自由装修', '户内', '起居']
    furnitureDetails?: {                // 家具特有属性
      scene: 'indoor' | 'outdoor' | 'background';
      isFloor: boolean;
      isGrowthProp: boolean;
      isSuit: boolean;
    };
  };
  
  // 归属信息
  ownership: {
    type: 'male_lead' | 'spy' | 'none';  // 归属类型
    name: string | null;                  // 人名："刘辩"、"阿蝉"
    code: string | null;                  // 拼音码："lb"、"achan"
  };
}
```

## 配置文件

### 1. parseConfig.json
**功能**：文件名段 → 人名/分类的映射

```json
{
  "男主映射": { "lb": "刘辩", "sc": "孙策" },
  "密探名映射": { "achan": "阿蝉", "sunfu": "孙辅" },
  "户外分类": { "jianzhu": "建筑", "jingguan": "景观" },
  "户内分类": { "qiju": "起居", "zhiwu": "置物" },
  "地板分类": { "diban": "地板", "outdoor_diban": "地面/水面" }
}
```

### 2. categoryConfig.json
**功能**：定义UI显示的分类树结构

```json
{
  "除家具以外的道具": {
    "男主类": ["男主元素", "男主言事章", "男主皮肤"],
    "密探类": ["密探礼物", "心纸", "自选密探"]
  },
  "家具": {
    "套装": ["户内", "户外"],
    "自由装修": {
      "户内": ["起居", "置物", "装饰"],
      "户外": ["建筑", "景观", "陈设"]
    }
  }
}
```

### 3. categoryOwnershipRules.json
**功能**：定义每个分类的归属规则

```json
{
  "categoryOwnershipRules": {
    "男主元素": {
      "defaultOwnership": "male_lead",    // 默认归属类型
      "extractFrom": "segments"            // 从文件名段提取
    },
    "密探礼物": {
      "defaultOwnership": "spy",
      "extractFrom": "segments"
    },
    "起居": {
      "defaultOwnership": "male_lead",
      "extractFrom": "furniture_segment",
      "allowNone": true                    // 允许无归属
    }
  }
}
```

## 解析流程

```
文件名: icon_s1001_lb_qiju_001.png
    ↓
1. 识别分类 → category: "起居"
    ↓
2. 识别归属 → 根据"起居"的规则，从家具段提取 → ownership: { type: "male_lead", name: "刘辩", code: "lb" }
    ↓
3. 生成展示名 → displayName: "刘辩-起居"
    ↓
4. 构建完整路径 → categoryPath: ['家具', '自由装修', '户内', '起居']
```

## 归属提取方式

| extractFrom | 说明 | 示例 |
|------------|------|------|
| segments | 从文件名段中提取人名 | icon_nz_lb_001 → 刘辩 |
| ccl_code | 从ccl编码第1位提取 | icon_ccl_1001 → 刘辩(1) |
| component_code | 从component编码第1位提取 | icon_component_11001 → 刘辩(1) |
| furniture_segment | 从家具格式段提取 | icon_s1_lb_qiju_1 → 刘辩 |
| avatar_pinyin | 从头像拼音提取 | icon_achan_s → 阿蝉 |

## 归属类型

| 类型 | 说明 | 颜色 |
|------|------|------|
| male_lead | 男主 | #D86B6B (红) |
| spy | 密探 | #4F73C7 (蓝) |
| none | 无归属 | #888 (灰) |
| mixed | 混合（可能是男主也可能是密探） | #C59F4A (金) |

## Tab4 规则管理

### 可管理内容

1. **男主映射** - 拼音码 → 男主中文名
2. **密探名映射** - 拼音码 → 密探中文名
3. **户外分类** - 代码 → 户外分类名
4. **户内分类** - 代码 → 户内分类名
5. **地板分类** - 代码 → 地板分类名
6. **归属规则** - 分类 → 归属类型和提取方式

### 操作功能

- ✅ 新增/编辑/删除规则
- ✅ 搜索过滤
- ✅ 导出为JSON
- ✅ 导入JSON
- ✅ 重置为默认

## 筛选功能

### Tab1 支持三种筛选

1. **分类筛选** - 按分类树结构筛选
2. **归属筛选** - 按归属类型和具体人名筛选
3. **关键词搜索** - 搜索文件名或展示名

### 组合示例

```
分类: 家具 > 自由装修 > 户内 > 起居
归属: 男主 > 刘辩
搜索: icon_s
→ 结果：刘辩的起居类家具，文件名包含"icon_s"
```

## 数据持久化

- **localStorage** - 所有规则和道具数据
- **自动迁移** - 旧格式数据自动升级
- **实时保存** - 修改规则立即生效

## 优势

✅ **清晰分离** - 分类与归属独立管理  
✅ **灵活扩展** - 新增分类只需配置  
✅ **统一处理** - 男主和密探同等对待  
✅ **可视化管理** - Tab4图形化编辑规则  
✅ **向后兼容** - 保留旧字段，自动迁移
