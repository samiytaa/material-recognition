## 基础概念

### 什么是文件名解析？
系统会自动读取图片文件名，识别其中的信息，生成中文显示名称和分类。

### 文件名分段规则
- 使用下划线 `_` 分割文件名
- 例如：`icon_sc_jianzhu_1001.png` → `["icon", "sc", "jianzhu", "1001"]`

---

## 解析流程

```
文件名
  ↓
去掉 .png 后缀和 #数字 标签
  ↓
按 _ 分割成段
  ↓
匹配特定格式模式
  ↓
查找映射表（男主、密探、分类）
  ↓
生成中文显示名
```

## 各类道具格式

### 1. 家具类（最常见）

**格式：** `icon_s数字_男主代码_分类代码_编号`

**示例：**
- `icon_s1_sc_jianzhu_1001.png`
  - `s1` = 第一季
  - `sc` = 孙策（查男主映射表）
  - `jianzhu` = 建筑（查户外分类表）
  - `1001` = 编号
  - **显示：** `孙策-建筑`

**初见日家具：** 带 `fd` 标记
- `icon_s1_fd_lb_qiju_2001.png`
  - `fd` = 初见日标记
  - `lb` = 刘辩
  - `qiju` = 起居（查户内分类表）
  - **显示：** `初见日-刘辩-起居`

**公用家具：** 男主代码为 `all`
- `icon_s1_all_diban_3001.png`
  - `all` = 所有男主通用
  - `diban` = 地板（查地板分类表）
  - **显示：** `地板`

---

### 2. 密探头像

#### 标准头像
**格式：** `icon_密探拼音_s`

**示例：**
- `icon_sunfu_s.png` → `密探头像-孙辅`
- `icon_zhangzhongjing_s.png` → `密探头像-张仲景`

#### 带连字符的换装
**格式：** `icon_密探拼音_换装代码_s`

**示例：**
- `icon_achan_huanfu-1_s.png`
  - 查找：`achan_huanfu-1` → `阿蝉·雾绡`
  - **显示：** `密探头像-阿蝉·雾绡`

#### QQ人头像/魂魂头像
**格式：** `icon2_拼音_尺寸` 或 `icon3_拼音_尺寸`

**示例：**
- `icon2_sunfu_l.png` → `魂魂头像-孙辅(大)`
- `icon3_zhangzhongjing_m.png` → `QQ人头像-张仲景(中)`
- 尺寸：`l`=大, `m`=中, `s`=小, `ss`=超小

#### 绒绒头像
**格式：** `icon_cat_拼音_尺寸` 或 `icon_dog_拼音_尺寸`

**示例：**
- `icon_cat_sunfu_l.png` → `猫绒绒-孙辅(大)`
- `icon_dog_zhangliao_red_m.png` → `狗绒绒-张辽-红(中)`

---

### 3. 男主相关道具

#### 男主回忆
**关键字：** `_hy_`

**示例：**
- `icon_sc_hy_1001.png` → `孙策-男主回忆`

#### 男主互动道具（CCL编码）
**格式：** `icon_ccl_4位数字`
- 第1位数字代表男主：1=刘辩, 2=傅融, 3=袁基, 4=左慈, 5=孙策

**示例：**
- `icon_ccl_3021.png`
  - 首位 `3` = 袁基
  - **显示：** `袁基-互动道具`

#### 男主装饰（Component编码）
**格式：** `icon_component_5位数字`
- 第1位数字 = 男主（同上）
- 第2位数字 = 套系：1=夕情欢馀, 2=春月柳, 3=燕歌行

**示例：**
- `icon_component_51023.png`
  - 首位 `5` = 孙策
  - 第2位 `1` = 夕情欢馀
  - **显示：** `孙策-夕情欢馀`

#### 男主皮肤
**关键字：** `_nz_skin_`

**示例：**
- `icon_sc_nz_skin_001.png` → `孙策-男主皮肤`

---

### 4. 初见日道具

#### 带 icon 前缀
**关键字：** `_cjr_`

**示例：**
- `icon_sc_cjr_1001.png` → `孙策-初见日道具`

#### 不带 icon 前缀
**格式：** `cjr_男主代码_编号`

**示例：**
- `cjr_lb_2001.png` → `刘辩-初见日道具`

### 5. 活动和礼包

#### 礼包
**关键字：** `_lb_` 或以 `_lb` 结尾（且不是家具格式）

**示例：**
- `icon_hd_qixi_lb.png` → `礼包`

#### 活动道具
**关键字：** `_hd_`

**示例：**
- `icon_hd_qixi_2023.png` → `活动`

#### 七夕活动
**关键字：** `_qxhd_`

**示例：**
- `icon_qxhd_1001.png` → `七夕活动`

## 归属识别规则

### 什么是归属？
每个道具可能归属于某个男主、密探，或者无归属（公用道具）。

### 归属类型
- **男主归属：** 道具属于某个男主（刘辩、傅融、袁基、左慈、孙策）
- **密探归属：** 道具属于某个密探
- **无归属：** 公用道具，不属于特定角色
- **混合：** 可能是男主或密探

### 归属提取方式

#### 1. 从文件名段提取（segments）
在文件名的各段中查找男主代码或密探拼音

**示例：**
- `icon_sc_hy_1001.png` → 找到 `sc` → 孙策
- `icon_sunfu_mt_skin_001.png` → 找到 `sunfu` → 孙辅

#### 2. 从CCL编码提取（ccl_code）
CCL编码第1位数字代表男主

**示例：**
- `icon_ccl_5021.png` → 首位 `5` → 孙策

#### 3. 从Component编码提取（component_code）
Component编码第1位数字代表男主

**示例：**
- `icon_component_31023.png` → 首位 `3` → 袁基

#### 4. 从家具格式段提取（furniture_segment）
家具格式中的男主代码位置

**示例：**
- `icon_s1_sc_jianzhu_1001.png` → 男主代码 `sc` → 孙策
- `icon_s1_all_diban_3001.png` → `all` → 无归属

#### 5. 从头像拼音提取（avatar_pinyin）
密探头像文件名中的拼音部分

**示例：**
- `icon_sunfu_s.png` → 拼音 `sunfu` → 孙辅

## 📝 规则优先级

解析时按以下顺序匹配，匹配到第一个符合的就停止：

1. 非 icon 开头的纯中文名或自定义名
2. `cjr_` 开头的初见日道具（无icon前缀）
3. 密探/绒绒头像（icon2/icon3/icon_cat/icon_dog）
4. 普通密探头像（_s 结尾）
5. 家具格式（icon_s数字_...）
6. 套装家具（含 _xzrhw_ 或 _xzr_）
7. 衬景（icon_xzr 开头）
8. 初见日道具（含 _cjr_）
9. 男主互动道具（_ccl_）
10. 男主装饰（_component_）
11. 礼包（_lb_）
12. 其他道具关键字匹配
13. 兜底规则（显示原文件名）

## 🔧 如何在 Tab4 中修改规则

### 修改男主映射
1. 进入 Tab4「规则管理」
2. 选择「男主映射」标签
3. 点击「新增」或编辑现有条目
4. 填写：
   - **键**：文件名中的代码（如 `sc`）
   - **值**：中文名称（如 `孙策`）
5. 保存后，在 Tab1 点击「重新解析」应用规则

### 修改分类映射
与男主映射类似，可修改：
- **户外分类**：如 `jianzhu` → `建筑`
- **户内分类**：如 `qiju` → `起居`
- **地板分类**：如 `diban` → `地板`

### 修改归属规则
1. 选择「归属规则」标签
2. 为每个分类设置：
   - **归属类型**：男主/密探/无归属/混合
   - **提取方式**：从哪里提取归属信息
   - **允许无归属**：是否允许该分类无归属

## ❓ 常见问题

### Q1：为什么修改规则后文件名没变化？
**A：** 需要在 Tab1 点击「重新解析」按钮，才会用新规则重新解析所有已导入的图片。

### Q2：如果文件名不符合任何格式会怎样？
**A：** 会被归类为「其他」，显示名为原文件名。

### Q3：可以添加新的分类吗？
**A：** 目前关键字分类是硬编码的，需要修改代码。但可以修改映射表中的现有分类名称。

### Q4：男主代码冲突怎么办？
**A：** 例如 `lb` 既是刘辩代码，也是礼包关键字。系统会优先匹配家具格式，如果不符合家具格式才会识别为礼包。

### Q5：密探拼音很长会影响识别吗？
**A：** 不会，系统会尝试所有可能的段组合。例如 `zhangzhongjing` 可以正确识别。

## 💡 最佳实践

### 文件命名建议
1. 保持下划线分隔的结构
2. 使用规范的代码和拼音
3. 避免特殊字符和空格
4. 在文件名末尾加 `#数字` 可自动去除（用于重复文件）

### 规则管理建议
1. 定期导出规则备份（Tab4 → 导出）
2. 批量修改时先测试小批量
3. 保持映射表的一致性
4. 文档化自定义规则的含义
